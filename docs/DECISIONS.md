# Решения и вопросы на согласование

ТЗ §30.3 запрещает придумывать бизнес-правила. Там, где ТЗ неоднозначно, ниже предложен конкретный вариант. Он реализован как **настройка или легко изменяемое правило** и ждёт подтверждения заказчика.

Статусы: ✅ утверждено · 🟡 предложено, реализовано, ждёт подтверждения · 🔴 нужен ответ или доступ заказчика.

## Утверждено

| # | Решение | Дата |
|---|---|---|
| D-01 | Стек: Next.js + NestJS + TS strict + PostgreSQL + Prisma; очереди, outbox и rate limit на PostgreSQL, без Redis | 2026-11-19 |
| D-02 | Локальная среда: Node, Git, PostgreSQL нативно; Docker-конфигурация только для production | 2026-11-19 |

## Предложено (реализовано, ждёт подтверждения)

| # | Вопрос ТЗ | Предложенное решение | Последствия |
|---|---|---|---|
| D-10 | §11 «единый клиентский профиль в пределах платформы» при изоляции организаций | Платформенный профиль клиента хранится в `users` (по телефону). В каждой организации есть своя карточка `clients (organization_id, phone)` со ссылкой на `user_id`. Организация видит только свою карточку и свои записи | Изоляция сохраняется, а клиент в кабинете видит записи во всех организациях |
| D-11 | §3.1 гостевая запись: как гостю перенести или отменить | После подтверждения OTP выдаётся секретная ссылка управления записью (токен хранится как хэш). Войдя по телефону и OTP, клиент видит все свои записи | Нет обязательной регистрации |
| D-12 | §2.3 «владельцы теряют платные функции» | При `expired` и `suspended` сотрудники могут войти и **читать** данные и страницу подписки, все изменения запрещены (`403 SUBSCRIPTION_INACTIVE`). В `grace_period` работает всё, показывается баннер | Данные не теряются, владелец видит, что нужно продлить |
| D-13 | §2.4 п.1 при `suspended` | Публичная запись отключена, страница показывает «Временно недоступно» с контактами (страница не скрыта). При `expired` после льготного периода страница скрыта | Различие между п.1 и п.2 ТЗ |
| D-14 | §5 + §12: акции и промокоды вместе | Временная акция применяется к цене услуги автоматически (из нескольких берётся одна, наибольшая). Промокод применяется к итоговой сумме визита после акций. Итог не бывает меньше 0 | Можно переключить на «не суммировать» |
| D-15 | §8.2 переходы статусов | `completed` и `no_show` финальные; админ может исправить `no_show → completed` в течение 24 часов (ошибочная отметка) | Отчётность корректна |
| D-16 | §8.3 «возможность продления резерва» | Клиент может один раз продлить резерв на ту же длительность (настройка `hold_extension_allowed`, по умолчанию да, максимум 1 раз) | |
| D-17 | §8.7 режим нескольких услуг | Настройка филиала `multi_service_mode`: `sequential` (по умолчанию) или `parallel`. Клиент может выбрать исполнителя для каждой услуги или «любой» | |
| D-18 | §14 публикация отзывов | Отзыв публикуется сразу. Владелец не может редактировать или скрывать отзыв, только отвечает или жалуется. Скрывает суперадмин с указанием причины. Оставить отзыв можно в течение 30 дней после `completed` | Нет «незаметного» изменения |
| D-19 | §17 уникальный посетитель | Без cookies: дневной хэш (соль, IP, UA, филиал). Уникальные за неделю или месяц считаются как сумма дневных уникальных, это задокументированное приближение | Не нужен баннер согласия на cookies |
| D-20 | §17 атрибуция | Last-touch в пределах сессии браузера (sessionStorage) с окном 30 минут бездействия; запись приписывается UTM визита, в котором начато оформление | |
| D-21 | §10 вход сотрудников | Сотрудники входят по email и паролю (argon2id), суперадмин с TOTP. Клиенты входят по телефону и OTP | Нет SMS-затрат на вход сотрудников |
| D-22 | Валюта | Цены хранятся целыми тенге (без тиын) | |
| D-23 | §13.5 автоперевод | Адаптер Google Cloud Translation (поддерживает казахский). Без ключа переводы остаются `missing`, посетитель видит основной язык | Нужен ключ (R-03) |
| D-24 | §9 Waitlist | Реализован (2026-11-21). Клиент встаёт в очередь из формы записи (услуги, специалист или «любой», диапазон дат ≤ 60 дней) с подтверждением номера OTP; администратор добавляет вручную с приоритетом 0–100. Отмена или перенос подтверждённой записи фиксирует освободившееся время. Воркер (каждые 20 с) отправляет предложение первым N подходящим клиентам одновременно. Подходящим считается слот клиента, который использует освободившийся ресурс в освободившееся время. Настройки владельца: включение (по умолчанию выключено), срок предложения (15 мин), число получателей (3), порядок (по времени или приоритет → время), действие после истечения (следующим в очереди или оставить слот для общей записи) | Выключено по умолчанию: поведение существующих филиалов не меняется |
| D-33 | §9 детали, не заданные ТЗ | 1) Запись по ссылке из предложения подтверждается без повторного OTP: ссылка с секретным токеном пришла на номер клиента (как ссылка управления, D-11). 2) На время предложения слот **не резервируется**: его может занять и обычная онлайн-запись; тогда предложение получает статус «потеряно», а заявка остаётся в очереди. 3) У клиента не больше 3 активных заявок в организации и не больше одного действующего предложения. 4) Отказ от предложения возвращает заявку в очередь; есть отдельная кнопка «Выйти из листа ожидания». 5) Если все получатели отказались, следующий раунд начинается сразу, без ожидания срока. 6) Защита от двойного назначения: блокировка филиала, EXCLUDE и уникальный индекс «одно принятое предложение на освободившееся время» | Варианты 2 и 3 легко изменить (например, резервировать слот на время предложения) |
| D-25 | §8.9 «ограничения по номеру телефона» | Максимум активных записей на номер в организации (по умолчанию 3) и запрет повторной записи на пересекающееся время | |
| D-26 | §8.4 конкурентная запись | Транзакции бронирования одного филиала сериализуются advisory-блокировкой; EXCLUDE-ограничение остаётся гарантией на уровне БД; взаимоблокировки (40P01) повторяются автоматически | Детерминированный автоподбор и отсутствие двойных броней. Около 24 резервов/с на один филиал (см. TESTING.md) |
| D-27 | §1.2 UTC | Сессия БД принудительно в UTC (`-c TimeZone=UTC`) | Найдено тестами: драйвер Prisma 7 передаёт даты без смещения, и при часовом поясе сервера Asia/Almaty время сдвигалось на 5 ч |
| D-28 | §3.2 ручная запись | Запись, созданная администратором, сразу `confirmed` без OTP (администратор подтверждает клиента сам); клиенту отправляется уведомление и ссылка управления | |
| D-29 | §20.5 social_links, page_assets | Соцсети хранятся в контенте черновика или публикации (чтобы подчиняться правилу «черновик → публикация»); таблица медиа названа `media_assets` (используется и для услуг, и для специалистов) | Отклонение от предварительного перечня таблиц ТЗ |
| D-30 | Версии | NestJS 11 (а не 12): nestjs-zod пока поддерживает только 11; Prisma 7.10 (8.x — RC); TypeScript 5.9 | Стек не меняется, выбраны совместимые стабильные версии |
| D-31 | §14 обезличивание | Триггер неизменяемости отзыва разрешает только замену имени автора на «Удалённый клиент» и переназначение `client_id` при объединении дублей | Содержание отзыва (оценка, текст) неизменяемо |
| D-32 | §15.1 «отвечать на вопросы о существующей записи» | **Заказчик выбрал автоответ (без чата с оператором).** На любое входящее сообщение клиент получает до 3 ближайших подтверждённых записей на свой номер во всех организациях: дату, время, филиал, адрес, услуги, телефон филиала, ссылку на кабинет. Ответ — обычный текст в 24-часовом окне Meta, не чаще 1 раза в 5 минут на номер. Повторная доставка webhook не даёт второго ответа: уникален id сообщения. Сообщения старше 24 ч, служебные типы (reaction и т.п.) и сообщения на чужой номер Meta игнорируются. Текст входящих не хранится, журнал хранится 30 дней. Создания записи через WhatsApp нет (запрещено §15.1) | Реализовано 2026-11-22 |
| D-34 | §15.1 «согласованные реактивационные сообщения» | **Заказчик выбрал автоматическую отправку.** Включает владелец (по умолчанию выключено) и задаёт N дней (30–365, по умолчанию 60). Через N дней после последнего завершённого визита клиент получает одно сообщение со ссылкой на страницу филиала (UTM `whatsapp / message / reactivation`), если выполнены все условия: нет будущих записей; есть согласие на рекламу (новая отметка в форме записи или в кабинете, по умолчанию выключено) и на уведомления и WhatsApp; номеру не отправляли реактивацию 30 дней; филиал принимает онлайн-запись; подписка активна; по времени филиала 10:00–20:00. Только WhatsApp, шаблон `reactivation` категории MARKETING. Отписка — «СТОП» / «ТОҚТАТУ» / «STOP» в ответ (для всех организаций, неотправленные реактивации отменяются) или в кабинете | Реализовано 2026-11-22. Нужен одобренный Meta шаблон `reactivation` (R-01) |
| D-35 | §3.4 «восстанавливать доступ» | Суперадмин задаёт сотруднику временный пароль: нужен повторный TOTP-код и причина. При следующем входе пароль обязательно меняется, все сессии пользователя отзываются, блокировка после неудачных попыток снимается, действие пишется в аудит (без пароля). Свой пароль — только через смену; у клиентов пароля нет (вход по OTP). Владелец (право users.manage) так же восстанавливает доступ администратору филиала своей организации, если тот не работает в других организациях: пароль общий для всех организаций пользователя. Сброс MFA суперадмина через интерфейс не предусмотрен: только скриптом `superadmin:create` на сервере. Самостоятельного восстановления пароля по email нет: канал email вне MVP | Предложено, требует подтверждения |
| D-36 | §22 сроки хранения | Воркер ежечасно удаляет: завершённые сообщения журнала уведомлений, попытки, статусы и события старше 365 дней; сырые аналитические события старше 730 дней (дневные агрегаты остаются); dev_inbox старше 7 дней; журнал входящих WhatsApp старше 30 дней. Неотправленные сообщения и ключи реактивации не удаляются. Автоматического обезличивания клиентов по сроку бездействия нет: это необратимо и требует утверждённого срока (сейчас — вручную владельцем) | Сроки — предложение до проверки юристом (`processing.md`), меняются в `RETENTION_DAYS` |
| D-37 | §18.3 раздел «Интеграции» | Доступы к WhatsApp, SMS и переводу подключает платформа (ключи в переменных окружения). Владелец видит их состояние, свои включения каналов, доставку за 7 дней и настройку карты по филиалам, без секретов. Собственные аккаунты WhatsApp организаций (`whatsapp_accounts`) зарезервированы в схеме, но не используются | Предложено |
