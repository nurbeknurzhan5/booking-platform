# Безопасность (ТЗ §22)

| Требование | Реализация | Где проверено |
|---|---|---|
| Безопасная авторизация | Непрозрачные сессии в HttpOnly cookie, в БД хранится только SHA-256 токена; скользящее продление с абсолютным пределом; отзыв всех сессий при смене пароля и блокировке. При входе (сотрудник, клиент по коду) прежняя сессия этого браузера отзывается | `saas-core.int.ts`, `security.int.ts`, `audit-d.int.ts` |
| Хранение паролей | argon2id (19 МБ памяти, t=2). Временные пароли нужно сменить при первом входе. Блокировка входа после 10 неудач | `security.int.ts` |
| MFA суперадмина | TOTP обязателен при входе. Критические действия (подписка, оплата, блокировка организации или пользователя, системные настройки) требуют повторный код в `X-MFA-Code`. Не больше 10 неверных кодов за 15 мин на пользователя (общий счётчик для входа и step-up), дальше `429`. Каждый временной шаг TOTP принимается один раз (`users.mfa_last_used_step`, RFC 6238 §5.2): код, которым выполнен вход, не годится для step-up, повтор → `403 MFA_INVALID` «Код уже использован…». Интерфейс запрашивает новый код для каждого действия и не хранит его | `saas-core.int.ts`, `audit-d.int.ts` |
| OTP | 6 цифр из CSPRNG; хранится HMAC-SHA256 с секретом и id кода; TTL 5 мин; 5 попыток (атомарное списание до сравнения); одноразовость; повтор не чаще 60 с на номер, 5/ч на номер, 30/ч на IP, 5000/ч глобально. В outbox код хранится зашифрованным (AES-256-GCM) и стирается после отправки. В логах кода нет | `booking.int.ts`, `notifications.int.ts`, `modules.int.ts` |
| Защита от перебора и массовых запросов | Rate limit на PostgreSQL для всех маршрутов, отдельные лимиты на вход, OTP, MFA, бронирование, отзывы, загрузки | `security.int.ts`, `audit-d.int.ts` |
| IP клиента за прокси | Next.js (rewrite) пропускает присланный клиентом `X-Forwarded-For` как есть, поэтому `TRUST_PROXY` = число **перезаписывающих** заголовок прокси перед Next.js: `1` только в production за Caddy (без `trusted_proxies` Caddy пишет адрес соединения), `0` локально, в CI/E2E и Codespaces (заголовок игнорируется, IP = адрес соединения, лимит общий на стенд); по умолчанию `0`. `trust proxy` в API — функция: не больше `TRUST_PROXY` хопов и только с внутренних адресов (loopback, 10/8, 172.16/12, 192.168/16, link-local, fc00::/7). Проверено через настоящий rewrite Next.js: при `TRUST_PROXY=1` без Caddy 25 запросов кода с разными `X-Forwarded-For` — 25×200 (обход), при `0` — 20×200, затем 429 (D-54) | `audit-d.int.ts`, `e2e/security.spec.ts` |
| Ошибки тела запроса | JSON больше 1 МБ → 413 `PAYLOAD_TOO_LARGE`, битый JSON → 400 с русским сообщением без текста парсера, неподдерживаемые кодировка/charset → 415; в журнал warn без стека (D-55) | `audit-d.int.ts` |
| Автоматизированные запросы | Honeypot-поле и минимальное время заполнения формы записи; лимиты по IP; номер должен быть мобильным номером КЗ | `booking.int.ts` |
| Подмена номера | Запись подтверждается только OTP, отправленным на указанный номер; привязка к профилю — только после подтверждения. Кабинет клиента (`/me`) ищет и привязывает записи, заявки листа ожидания и согласия платформы по телефону только при подтверждённом номере (`users.phone_verified_at`); так же `finalizeHold` и подтверждение заявки листа ожидания. Номер, указанный сотруднику без подтверждения, не открывает чужие записи: вход по коду на такой номер создаёт отдельный клиентский профиль и снимает номер с профиля сотрудника (аудит `user.unverified_phone_released`) | `booking.int.ts`, `modules.int.ts`, `audit-c.int.ts`, `audit-d.int.ts` |
| Серверная проверка прав | Глобальные guard'ы: аутентификация → CSRF → rate limit → tenant → RBAC → подписка; secure-by-default (маршрут организации без явного права доступен только владельцу). Переводы: страница и специалист — `pages.edit` в их филиале; услуги, категории и акции (уровень организации) — только владелец или суперадмин. `canEdit` страницы у суперадмина — только в сессии с MFA | `saas-core.int.ts`, `security.int.ts`, `audit-d.int.ts` |
| Изоляция организаций | Tenant context из сессии и членства; чужие ресурсы → 404; составные FK `(organization_id, id)` в БД; ссылки на файлы (`MediaService.urlsFor`) — только на файлы своей организации | `saas-core.int.ts`, `security.int.ts`, `audit-d.int.ts` |
| SQL injection | Prisma (параметризованные запросы), raw-SQL только через tagged templates `$queryRaw` | `security.int.ts` |
| XSS | React-экранирование; ссылки только http(s); SVG запрещены; CSP (API и web). Карта `/embed/map`: подпись (`title`, название филиала) — только через `textContent`, Leaflet получает DOM-узел, а не HTML-строку; сообщения `2gis-set`/`2gis-pick` принимаются только от своего окна (родитель или свой iframe) и только с конечными координатами (широта до ±90, долгота до ±180). CSP сайта: `script-src-attr 'none'` (inline-обработчики запрещены), `Cross-Origin-Opener-Policy: same-origin`; `script-src 'unsafe-inline'` остаётся (inline-скрипты гидратации Next.js, nonce требует динамического рендеринга — бэклог). Пути запросов к API собираются тегом `apiPath` (подстановки кодируются, `.` и `..` запрещены); не-UUID `orgId`/`branchId` в адресе кабинета → 404 | `pages.int.ts`, `shared.test.ts`, E2E `security.spec.ts` |
| CSRF | Double-submit токен `bk_csrf` + `X-CSRF-Token` (сравнение за постоянное время), SameSite=Lax | `saas-core.int.ts` |
| Файлы | Лимит 5 МБ, белый список JPEG/PNG/WebP, проверка сигнатуры, MIME и декодирования (sharp), лимит разрешения 8000×8000, без анимаций, перекодирование в WebP без метаданных, ключи хранилища генерирует сервер (защита от path traversal), раздача с `nosniff` и `CSP: default-src 'none'` | `pages.int.ts` |
| Секреты | Только переменные окружения, проверка конфигурации при старте (Zod). Токены интеграций и MFA-секреты шифруются AES-256-GCM (`authTagLength` 16). Секреты не входят в репозиторий (`.gitignore`) | — |
| Токены и учётные данные в журналах | API (pino): путь без query, сегмент после `manage`, `waitlist-offers`, `confirm` → `[REDACTED]`, заголовки запроса и ответа не пишутся. Caddy (`infra/Caddyfile`, `format filter`): в `request>uri`, `Referer` и `Location` сегмент после `manage`, `confirm`, `waitlist`, `waitlist-offers` → `[REDACTED]`, query → `?[REDACTED]`; `Cookie`, `Authorization`, `Proxy-Authorization`, `X-Csrf-Token`, `X-Mfa-Code`, `Idempotency-Key`, `Set-Cookie` не пишутся. Страницы с токеном в адресе (`/{locale}/manage/…`, `/confirm/…`, `/waitlist/…`, `/dev/phone`) отдаются с `Referrer-Policy: no-referrer` и `X-Robots-Tag: noindex, nofollow`. Журнал `next start` адреса запросов не пишет | `audit-d.int.ts`, E2E `security.spec.ts` |
| Секреты в очереди уведомлений | OTP, ссылки подтверждения, предложения листа ожидания и ссылки управления (`appointment_confirmed`, `appointment_rescheduled` по ссылке) хранятся в outbox зашифрованными (AES-GCM, `payload_encrypted`) и стираются после отправки. В DLQ одноразовые секреты стираются; подтверждение и перенос записи остаются зашифрованными до ручного повтора или истечения | `notifications.int.ts`, `audit-c.int.ts` |
| Тестовый телефон | `GET /api/v1/dev/inbox` и страница `/dev/phone` работают только при `DEV_INBOX_ENABLED=true` (сайт — `NEXT_PUBLIC_DEV_INBOX_ENABLED=true` при сборке) и `APP_ENV≠production`, иначе 404, ссылки «Открыть тестовый телефон» нет. Флаг ставится автоматически только в Codespaces (`.devcontainer`) и в CI/E2E | `audit-e.int.ts` |

### Обезличивание: что сохраняется и почему

| Данные | Что происходит | Основание |
|---|---|---|
| Согласия организации (`client_consents`) | Запись остаётся без номера и IP | Доказательство законности обработки до отзыва |
| Общие согласия платформы (`organization_id IS NULL`, «СТОП») | Не меняются | Отказ от рекламы действует во всех организациях; организация не управляет платформенным профилем |
| OTP входа и листа ожидания | Не привязаны к организации: номер и HMAC кода, удаляются через 7 дней | Организация не может их адресовать; короткий срок |
| `rate_limit_buckets` | Удаляются через 1 час | Технические счётчики |
| `idempotency_keys.response_body` | Удаляются по сроку (48 ч) | Повтор запроса должен вернуть тот же ответ |
| `whatsapp_inbound_messages` | Удаляются через 30 дней (D-36), текст не хранится | Защита от повторной доставки webhook |
| Текст отзыва, `appointment_status_history.reason` | Не меняются | Неизменяемость отзывов (§14, D-31) и истории статусов |
| `users` (платформенный профиль) | Организация только отвязывает карточку | Профиль общий для всех организаций (D-10) |

## Что требует внимания до запуска

1. **Юридическая проверка** (R-06, R-07). Тексты в `docs/legal/` — черновики. Нужно проверить соответствие Закону РК «О персональных данных и их защите»: требования к согласию, локализации баз ПД на территории РК, трансграничной передаче (номер телефона уходит в Meta при отправке через WhatsApp), срокам хранения.
2. **Хостинг в РК** (R-05): база данных с ПД граждан РК должна находиться на территории РК.
3. **Антивирусная проверка файлов.** Перекодирование через sharp обезвреживает встроенное содержимое. При необходимости можно подключить ClamAV в воркере.
4. **WAF и DDoS-защита** на уровне провайдера или CDN: rate limit приложения не защищает от объёмных атак.
5. **Пентест** на согласованной инфраструктуре.
