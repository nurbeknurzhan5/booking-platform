# Онлайн-проверка без хостинга: GitHub Codespaces

Codespaces запускает весь проект (PostgreSQL, API, воркер, сайт) на облачной машине GitHub и даёт
https-ссылку на сайт. Покупать хостинг для проверки не нужно.

**Бесплатно:** личный аккаунт GitHub получает 120 «ядро-часов» в месяц: это около 60 часов работы
стенда на 2-ядерной машине и 15 ГБ места. Остановленный Codespace часов не тратит.

## 1. Выложить проект на GitHub

1. На github.com нажмите **New repository**, задайте имя (например, `booking-platform`) и выберите
   **Private**: в репозитории ТЗ и документы проекта. Ничего не добавляйте (README, .gitignore), репозиторий должен быть пустым.
2. В папке проекта выполните:

   ```bash
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/booking-platform.git
   git push -u origin main
   ```

   При первой отправке Windows откроет окно входа в GitHub.

Секреты в репозиторий не попадают: `.env`, `.local/` и сессии тестов исключены в `.gitignore`.

## 2. Запустить стенд

1. В репозитории на GitHub нажмите **Code → Codespaces → Create codespace on main**.
2. Первый запуск занимает 5–8 минут: установка, база, миграции, демо-данные, сборка. Ход виден в терминале
   (`View creation log`).
3. Когда в терминале появится «Стенд запущен», откройте вкладку **PORTS** и нажмите на адрес порта **3000**
   («Сайт»). Ссылка вида `https://<имя>-3000.app.github.dev`.

Следующие запуски проходят за ~30 секунд: данные и секреты сохраняются, пока Codespace существует.

## 3. Что проверить

| Что | Где |
|---|---|
| Демо-страницы | `/ru/b/demo-salon`, `/ru/b/demo-club`, `/ru/b/demo-sauna` |
| Кабинет владельца | `/login`: `owner@demo.kz`, `club@demo.kz`, `sauna@demo.kz`, пароль `DemoOwner12345` |
| Администратор филиала | `admin@demo.kz` / `DemoAdmin12345` |
| Суперадминистратор | данные — в файле `.local/superadmin.txt` (пароль и ключ для Google Authenticator) |
| Сообщения клиентам вместо WhatsApp | `/dev/phone` («Тестовый телефон»): ссылки подтверждения записи, коды входа, напоминания |
| Документация API (Swagger) | `/api/v1/docs` |

Запись: выберите услугу и время, введите любой номер `+7 70X…`, откройте `/dev/phone` и нажмите на ссылку
в сообщении — запись подтвердится.

## 4. Показать сайт другим

По умолчанию ссылка открывается только вам (после входа в GitHub). Чтобы её открыли другие люди:
**PORTS → порт 3000 → правая кнопка → Port Visibility → Public**.

Учтите: «Тестовый телефон» показывает сообщения всем, у кого есть ссылка, — это тестовый стенд,
вводите только тестовые номера и данные.

## 5. Управление стендом

| Действие | Команда в терминале Codespace |
|---|---|
| Перезапустить сервисы | `bash .devcontainer/start.sh` |
| Логи | `tail -f .local/api.log` · `.local/worker.log` · `.local/web.log` |
| После `git pull` с изменениями | `bash .devcontainer/setup.sh && bash .devcontainer/start.sh` |
| Вернуть демо-данные к исходным | `npm run db:reset:dev -w @booking/api -- --yes` |
| Тесты | `npm test` (unit + integration) |

**Остановите Codespace, когда закончили:** github.com → Codespaces → `…` → Stop. Неактивный
Codespace останавливается сам через 30 минут. Удалённый Codespace теряет базу; при следующем создании
демо-данные появятся заново.

## 6. Автоматические проверки (GitHub Actions)

- **CI** запускается при каждом push в `main`: линтер, проверка типов, unit и integration-тесты
  на PostgreSQL 17, сборка. Результат — во вкладке **Actions**.
- **E2E** (Playwright, 4 устройства) запускается вручную: **Actions → E2E → Run workflow**.

## Ограничения стенда

- WhatsApp, SMS, автоперевод и S3 не подключены (нужны ключи, см. R-01…R-05 в [TASKS.md](TASKS.md)):
  сообщения видны в «Тестовом телефоне», файлы хранятся на диске Codespace.
- Карта 2ГИС без ключа — временная (D-43). С ключом `NEXT_PUBLIC_2GIS_KEY` в `apps/web/.env.local` и пересборкой
  сайта включается официальная карта MapGL.
- Это стенд для проверки, а не рабочий сервер: для клиентов нужен хостинг в Казахстане (R-05) и запуск
  по [OPERATIONS.md](OPERATIONS.md).
