# Правила обработки персональных данных, сроки хранения, удаление и обезличивание

> ЧЕРНОВИК для согласования с юристом и заказчиком. Сроки — предложения разработчика.

## 1. Тексты согласий (версия 2026-11-v1)

Версия текста сохраняется вместе с каждым согласием (`client_consents.text_version`).

| Тип | Где даётся | Текст |
|---|---|---|
| `personal_data` (обязательно) | форма записи | «Я согласен(а) на обработку моих персональных данных (имя, номер телефона, сведения о записи) [Оператором платформы] и организацией, в которую я записываюсь, в целях оформления и обслуживания записи, в соответствии с Политикой конфиденциальности» |
| `notifications` | форма записи, кабинет | «Получать уведомления о записи (подтверждение, напоминание, перенос, отмена, запрос отзыва)» |
| `whatsapp` | форма записи, кабинет | «Получать уведомления через WhatsApp. Я понимаю, что номер телефона и текст уведомления передаются компании Meta Platforms (возможна трансграничная передача)» |
| `marketing` | кабинет (по умолчанию выключено) | «Получать согласованные информационные и реактивационные сообщения от организаций» |

Журнал согласий хранится только на добавление. Отзыв согласия — новая запись `granted = false`. Сообщения с кодом подтверждения являются частью услуги и отправляются независимо от согласия на уведомления.

## 2. Сроки хранения (предложение)

| Данные | Срок |
|---|---|
| Записи и история визитов | 3 года после последнего визита, затем обезличивание |
| Карточка клиента | до отзыва согласия или 3 года бездействия, затем обезличивание |
| Отзывы | пока опубликованы; при обезличивании клиента имя заменяется |
| Коды подтверждения (хэши) | 7 дней |
| Сессии | до 90 дней |
| Аналитические события (без ПД, хэш посетителя) | 2 года |
| Журнал уведомлений | 1 год; параметры кодов стираются сразу после отправки |
| Журнал аудита, оплаты, история подписок | 5 лет (бухгалтерский и налоговый учёт) |
| Резервные копии | 14 дней ротации |

## 3. Процедура удаления и обезличивания

1. Запрос субъекта поступает в организацию или Оператору платформы.
2. Владелец организации нажимает «Обезличить данные» в карточке клиента (`POST /organizations/:orgId/clients/:id/anonymize`). Условие — у клиента нет активных записей. Имя заменяется на «Удалённый клиент», телефон — на технический идентификатор, заметки удаляются, связь с аккаунтом разрывается, имя в отзывах обезличивается. Действие фиксируется в журнале аудита.
3. Удаление платформенного аккаунта выполняет суперадминистратор через блокировку пользователя. Его карточки во всех организациях обезличиваются по п. 2.
4. Резервные копии с этими данными перезаписываются в течение срока ротации.
5. Ответ субъекту даётся в срок, установленный законодательством РК.

## 4. Доступ к данным

- Администратор филиала видит только клиентов, у которых есть записи в его филиалах.
- Владелец видит клиентов своей организации.
- Суперадминистратор имеет системный доступ; его критические действия фиксируются в журнале аудита.
- Организации не видят данные друг друга.
